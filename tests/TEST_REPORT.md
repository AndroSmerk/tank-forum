## 4. Найденные проблемы

### 4.1. Rate Limiting (средняя)
- **Описание**: Окно rate limiting — фиксированное (FixedWindow). При пачке из 101 быстрого запроса часть может не попасть в одно окно.
- **Эндпоинт**: Любой (настроен глобально в `Program.cs`)
- **Рекомендация**: Рассмотреть SlidingWindow для более честного распределения, либо увеличить лимит до 200/мин.

### 4.2. Удаление тем и постов — только админ (информационно)
- **Описание**: DELETE /api/topics/{id} и DELETE /api/posts/{id} доступны только с политикой `AdminOnly`. Пользователи не могут удалять свои темы/посты.
- **Эндпоинты**: `DELETE /api/topics/{id}`, `DELETE /api/posts/{id}`
- **Рекомендация**: Если задумано, что пользователи могут удалять своё — нужно добавить проверку владельца или отдельный эндпоинт.

### 4.3. Отсутствие тестовых данных после перезапуска (низкая)
- **Описание**: Seed-данные загружаются только при первом запуске (`if (!ctx.Users.Any())`). При пересоздании БД данные не появляются автоматически.
- **Рекомендация**: Добавить `EnsureCreated` или миграцию с seed.

### 4.4. Сообщения чата без rate limit (низкая)
- **Описание**: ChatController не имеет отдельного rate limiting, только глобальный 100/мин. При высокой активности чата можно заблокировать все запросы пользователя.
- **Рекомендация**: Добавить отдельный rate limit для `/api/chat` (например, 30/мин).

## 6. Рекомендации

1. **Rate Limiting**: Заменить `FixedWindow` на `SlidingWindow` для более предсказуемого поведения.
2. **Удаление контента**: Добавить эндпоинты для удаления своих тем/постов обычными пользователями (сейчас только Admin).
3. **Seed-данные**: Вынести инициализацию в отдельную миграцию, чтобы данные гарантированно присутствовали.
4. **Мониторинг чата**: Ограничить частоту отправки сообщений в чат через клиент (debounce 1-2 сек).
5. **Документация**: Добавить `[ProducesResponseType]` атрибуты в контроллеры для полной генерации Swagger-документации.
